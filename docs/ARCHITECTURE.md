# 实现边界

## 按应用和场景编写流程

小红书只是当前支持的场景。后续知乎、B站，以及同一应用内差异较大的任务，分别以专门的代码实现页面识别、导航、提取、展开、终止判断和恢复逻辑，并分别做回归验证。不要求它们适配同一套图文轮播或评论流程。

仅在语义确实相同时复用底层能力，例如节点快照、截图、OCR、受控手势、任务暂停、存储和导出。应用特有的交互与完整性判断由该场景代码负责；不以减少重复为由把这些差异堆进参数、策略字符串或不断扩大的配置解释器。

项目不建设低代码适配平台，不规划用户编写流程配置、JSON DSL 或规则编辑器。新增平台先写该平台的具体实现，出现经验证相同的能力后再考虑提取公共代码。

## 当前代码与后续边界

- `core/`：Android 无关的不可变 UiSnapshot/UiNode/UiBounds、受限 JSON 规则、候选定位器、页码与轮播状态校验、评论解析与启发式去重、GKD ZIP/JSON 导入。可运行 JVM 回归测试。
- `capture/`：AccessibilityService 与小型操作悬浮层、每次动作新读节点树、截图窗口坐标转换、有限手势、共享任务生命周期、容量1的图像队列、ML Kit bundled OCR。原生节点引用不跨动作缓存。
- `capture/apps/xiaohongshu/`：小红书图文轮播、OCR、评论与回复流程。
- `capture/apps/zhihu/`：知乎当前回答的识别、正文读取、滚动与问题/作者校验；不调用小红书流程。
- `capture/apps/bilibili/`：B 站视频简介、播放统计、主评论与独立回复详情页。
- `data/`：Room 内部库，原始结构化 JSON 与用户校正文本同时保存。checkpoint 不覆盖已明确保存的人工校正。
- `export/`：纯文本/Markdown/JSON，逐页来源、评论父级、完整性与错误。只通过 UI 明确复制、分享或 SAF 导出。
- `MainActivity`：披露与授权引导、状态、笔记搜索、预览编辑、导出。

`CaptureApp.detect(packageName)` 仅按完整包名识别当前 App，`CaptureTaskFactory` 显式创建对应实现。`CaptureTask` 只约定开始、暂停、继续三个生命周期方法，不定义页面结构、导航步骤、提取字段或结束条件。停止由服务取消任务协程，各任务负责保存已有结果。

服务在空闲时只观察前台包名元数据，更新悬浮入口；不会自动开始读取正文。用户点击“提取”时重新读取前台包名，不信任旧标签，不提供平台选择器。小红书显示图文/评论/回复选项，知乎显示当前回答入口，知乎不受小红书的选项开关影响。未知应用拒绝自动采集，仍可主动生成单页快照。

新增 App 的步骤：在 `CaptureApp` 中登记包名和显示名；新增 `capture/apps/<app>/` 下的具体任务与页面识别代码；在工厂登记构造入口；如内容语义不同，增加对应结果模型、导出与界面呈现；提供该场景的合成回归和真机验证。一个 App 内不同场景的识别与分派也写在该 App 的代码内，不把流程放入注册表或 JSON。

历史 `CaptureProfile` 和内置 JSON 定位规则仅由 `XiaohongshuCaptureTask` 使用，保留现有输入限制与验证。它们不是跨 App 扩展协议；知乎使用独立 Kotlin 代码，后续平台同样无需适配小红书轮播模板。

## 知乎回答

基于用户提供的原生回答详情快照及真机测试，要求开始时问题标题、回答作者及正文可识别。范围为“问题下当前打开的一条回答”的无障碍可读文本；用户明确不需要知乎图片 OCR。没有实现问题回答列表自动点入、下一条回答导航、全部回答遍历、评论或付费展开。不能把“下一篇内容”直接当成“同一问题下一条回答”。

`ZhihuPageReader` 按文档顺序读取回答容器的正文行和可读图片说明，排除工具栏、关注、点赞计数与容器外文本。同一个 RecyclerView 内可能同时存在当前回答的页脚、评论及下一条回答；只读取当前作者分段，遇到其 `end_info_view` 或 `out_comment_view` 即确认回答结尾，下一作者段落不得混入。`ZhihuAnswerCaptureTask` 独立控制滚动；每次动作前核对窗口、尺寸、问题（仍可读时）与作者；暂停后要求原问题标题重新可见。最多尝试40段页面、10分钟，连续两次可读内容不变只停止尝试，不视为全文结束。

`CapturedAnswer` 与图页、评论分开，保留作者、拼接文本、各段原始段落/图片说明/图片数、回答结束标记及异常；仅消除相邻视口的整段重叠，不做全局同文去重。明确读到当前回答结尾且没有运行错误时，可读文本采集标为 `complete`，不因未做图片 OCR 降级；未确认结尾、达到上限或中断则保留 `partial`/`stopped`。完成状态只针对该回答可访问的节点文本，不表示已获得问题全部回答或节点未提供的隐藏文字。没有稳定回答ID、同作者同问题多回答、局部段落截断、同文视口和异步加载仍有边界。

知乎结构化导出为 schemaVersion 3，带 `captureKind=zhihu_answer` 和 `answers[].observations`；旧笔记与小红书导出仍为版本2，新增字段不要求数据库迁移。Room继续保存原始 JSON 与人工校正文本，旧记录直接显示保存文本，不做破坏性重写。

## B 站视频

`BilibiliVideoCaptureTask` 独立处理国内版 `tv.danmaku.bili` 视频详情页。进入简介、展开并记录 BV 号、标题、UP 主、原始简介，以及页面提供的播放量、弹幕量、发布时间、在线人数、点赞、投币、收藏和分享数。保留“万”等显示单位，未提供的字段保持空值，不把推荐视频的时长或广告标题混入当前视频。

评论按 `cmt3_recycler` 行结构解析。主评论后的“共 N 条回复”进入独立详情页，先核对父评论作者和正文，再保存子评论与父级关联。预览回复可能截断，因此从详情页读取全文。每次动作重新验证窗口与控件，回复采集后关闭详情返回主列表。显式结尾或已读回复数达到该楼层显示数量才确认楼层完成；无进展、上限、中断保留部分结果。恢复要求回到原视频展开的简介核对 BV 号。结束前再次核对视频身份。

B 站 JSON 为 schemaVersion 4，`captureKind=bilibili_video`，视频信息放在独立 `video` 对象，评论包含 `parentId`。标题、简介、元数据与评论同时写入 Markdown。无需迁移旧数据库，不改写已有笔记或人工编辑文本。

B 站 ViewPager 会保留隐藏的简介节点，识别时优先排除可见评论列表，不能用缓存简介代替前台页。主列表里的短回复保存为 `textState=preview`；展开该楼层后移除预览，再保存详情正文，避免截断预览与全文重复。底部“展开更多评论”可能把内容插回列表上方，因此展开后回到首条重新遍历。“已为您展开部分评论”仅表示当前可见列表结束；页面宣称的评论数量单独保留，不据此声称所有服务器评论可访问。

每次任务进入评论页后，先回到“热门评论”等列表头再开始收集，避免继承前次任务的底部位置。暂停后重新核对视频时，未完成的回复楼层会重新尝试，已采数据按指纹合并。

## 主动结束

“保存并结束”是正常操作。三个 App 的任务取消时保存已有内容，状态为 `stopped`，不把停止原因写进 `errors`；界面与文本导出显示“已保存”。JSON 仍保留实际 `endReached`、已采数量及此前发生的真实异常，不把用户停止伪装成遍历完整。切换页面引起的暂停也不增加错误。

## 小红书真机手势范围

部分版本的 `noteDetailRV` 节点延伸至固定输入栏后方，直接按整个节点计算手势会从输入栏内起滑而无法推进。`XiaohongshuPageGeometry` 将评论手势裁到可见 `engageBarLayout` 上沿；区域过小则要求人工露出评论。原生滚动即使返回成功也验证视口变化，无实际推进时仅在重新校验后的评论区域执行受控滑动。

可见 `loadMoreTV` 明确显示“还没有评论哦”且尚未采到评论时，将显示评论数记为0并正常结束，不继续滚动。

## 诚实降级

未知页码不猜测总量；当前实现要求可验证的页码才自动翻页。截图完全重复、跳页、总数变化、OCR空文本均保留不完整状态。列表不再变化仅记“疑似到底”，不等于确认全部评论。无稳定源ID时评论指纹不能绝对识别所有重复/同文情况。屏外节点已有文本可读取，但动作/截图仅限可见有效区域。

每个任务保留已完成页和错误。恢复仅在同一笔记窗口重新验证后继续；进程被杀后保留 Room checkpoint，但不自动恢复后台手势。截图未写入磁盘，不提供原图永久留存功能。

## 保存与中断保障
保存由进程级串行写入器完成，不随无障碍服务协程一起取消；每个笔记仅保留最新待写checkpoint。Room事务保留已保存的人工校正，编辑只更新编辑列而不回滚采集结构。清空操作写入时间标记，旧会话排队结果不能复活已清空记录。进程被系统强杀仍可能丢失最后一个尚未落盘checkpoint，因此重要结果请导出。

版本2数据库提供1→2非破坏迁移；本次未在手机上执行迁移测试。页面没有稳定源笔记ID时，同窗口静默替换且身份字段缺失仍无法绝对识别；现有防护为初始身份字段、Activity/窗口事件、页码、尺寸和页面锚点验证，不声称适配所有未报告的界面变化。
