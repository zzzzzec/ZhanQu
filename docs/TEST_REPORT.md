独立测试驱动新增允许观察 `com.zhihu.android`，构建通过；产品采集入口仍只支持现有小红书流程。本轮没有获得可验证的知乎页面节点，因此未制定具体正文定位、翻页或评论规则，未新增知乎 profile 或宣称完成提取适配。后续在可运行的环境中观察回答、文章及评论，再分别以专门代码设计流程。

## 模拟器环境验证（2026-10-21，香港时间）

本机已安装 Android Emulator 稳定版 37.2.12、Android 16 Google APIs x86_64 revision 7，两个下载文件与 Google 官方仓库 SHA1 一致。独立虚拟设备 `ZhanQu_API36` 使用 WHPX 硬件加速、4GB 内存，序列号 `emulator-5580`；账号和应用数据独立于真机。

模拟器正常开机并通过 ADB 连接，支持 x86_64 与 ARM64 翻译。已安装同版本小红书 9.49.2 和原生 x86_64 的 `dev.zhanqu.app.devtest`。四项界面自动测试 `OK (4 tests)`，耗时 35.687 秒，截图提取成功；结果目录 `reports/device-test/20261021-224652-7ed9148c/`。这只证明基础界面自动操作，不代表小红书登录成功或提取质量已经在模拟器验收；登录由用户手动完成。

随后用户实际打开小红书出现 ANR。模拟器日志记录多次 `com.xingin.xhs` 的 `SIGSEGV`，并有 `/system/bin/arm64/app_process64` 加载 x86_64 `libc++.so` 的架构不匹配错误。已停止模拟器中小红书的反复启动，未清除数据；当前手机拆分安装包在该模拟器上的使用验收失败，不能以 `am start` 返回成功认定可正常登录。诊断保留在本机 `.gradle/local-tools/xhs-emulator-*` 文件。

按用户要求已从应用宝手机详情页取得国内 ARM64 完整版 9.51.0（versionCode 9510803），APK 与商店下载链接中的 MD5 一致，APK 签名验证通过。其证书与手机复制版不同，标准覆盖安装被 Android 以 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 拒绝。用户明确同意后仅卸载了模拟器旧版并安装国内版，真机未受影响。

国内版通过欢迎提示后仍出现 `SIGSEGV` 并退出。新崩溃的主线程栈涉及 `libjavacrypto.so` 的 SSL/JNI 回调，另有线程经过 `libtiny.so`；具体根因尚未完全定位，不能把崩溃确定归因于单个组件。已拒绝非必要通知权限并确认返回模拟器桌面、应用进程不存在。Android 16 模拟器上的小红书使用验收仍未通过，后续用较旧的官方系统镜像对照验证。
