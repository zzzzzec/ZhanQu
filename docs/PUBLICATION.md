# 公开发布与隐私检查

## 本次源码准备范围

- 审查源文件、配置、文档、测试样本及 Gradle wrapper 文件清单。
- 不随公开源码发布原始采集快照、图片、笔记数据库、导出内容、历史构建日志或机器生成报告。
- 文档不保留私人设备反馈、原始快照文件名、私人测试观察或本机绝对路径。
- 合成 fixture 保留公共 Android 包名、控件资源 ID、节点层级和几何；自由文本为合成占位符。数值是回归条件，不是对真实账号或内容的陈述。
- 不随源码发布签名私钥、凭证、环境变量文件或本机 SDK 配置。
- 输入源码未携带项目 Git 历史。首次公开应从经审查文件建立新仓库，不能连同旧工作区或未知历史上传。

本清单是审查结果与操作规范，不是对今后提交的自动安全保证。

## 文件白名单

完整相对路径见 [PUBLIC_FILES.txt](PUBLIC_FILES.txt)。发布程序应只暂存白名单内的文件，不能简单上传整个工作目录。新增文件应先审查内容，再加入白名单。

`.gitignore` 只是防误提交辅助：它不能清除已经跟踪的文件，也不能替代对 Git 历史、issue、附件、构建日志和 Release 资产的检查。

## 每次发布前

1. 核对 `git diff --cached` 与所有待提交文件，确认与白名单一致，无符号链接指向外部内容。
2. 扫描密钥、token、证书、私有 URL、账号、设备标识、绝对路径和采集原文；人工复核命中项。
3. 检查 Git 历史与提交作者信息，只使用已获许可的公开署名；不能沿用未知私有历史。
4. 执行构建、单元测试与 lint，明确记录跳过项、警告和未验证设备行为。不要公开未经清理的原始日志。
5. 对任何 APK 单独验证签名、权限、内嵌内容及校验和；不要把签名私钥加入仓库。清除调试数据不等于重置签名。
6. 如添加截图或演示，只用合成内容，检查状态栏、通知、头像、用户名、文件路径和背景。
7. 复核项目 LICENSE 和第三方依赖条款。当前没有为原始应用选择公共开源许可证，不要添加相矛盾的许可证徽章。

## 反馈问题时

公开 issue 只提交脱敏的步骤、版本、异常类型和必要合成样本。截图、错误消息和 JSON 都可能含个人数据；分享前必须查看完整内容。不要把个人导出 JSON 当作默认附件。
